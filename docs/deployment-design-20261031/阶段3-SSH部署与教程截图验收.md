## 先准备远端交互桌面

SSH 负责文件传输、调度与日志检查。Windows MCP、EVS、可见安装终端和原图截图必须属于同一个已登录、未锁定的远端交互会话。先记录 Windows 版本／构建、活动会话 ID、用户、显示器布局、分辨率、缩放和任务会话 ID；不能把 SSH shell 所在会话直接当成交互桌面。

若已有活动桌面，复用该桌面。需要桌面连接时先检查现状，不登出既有用户、不结束无关会话、不设置自动登录。远端桌面尚不可用时，可以继续下载／校验等独立工作；截图和交互验收保持未完成，不能用本机 SSH 终端图、黑屏或重建的示意图顶替。Windows Server 等未在上游支持列表明确列出的系统，须记录实际系统并验证兼容性，不能仅凭内核相近宣称通过。

## Windows MCP 安装与连接

1. 在新安装根内预留 `_agent_tools/windows-mcp/`，包含工具自身 Python、venv、uv、下载／缓存、配置、启动脚本、任务 XML、日志。该目录不进入 EVS 发布包、HF 资源或 EVS 依赖锁；也不使用 EVS common 环境安装 MCP。
2. 使用官方 uv Windows 便携文件，核对所选 uv 发行版本与校验和。设置进程级 `UV_CACHE_DIR`、`UV_PYTHON_INSTALL_DIR`、`TEMP/TMP` 到工具目录，再下载工具自己的 Python 3.14。记录最终具体 Python 补丁版本、来源、下载哈希与依赖冻结清单。保留原有系统 Python 和全局 PATH。
3. 以下是安装轮廓，路径由本轮安装根展开；Python 子版本与 uv 版本由执行者核实并记录后固定，不能把占位符直接执行：

   ```powershell
   & <工具目录的uv.exe> python install <已固定的3.14补丁版本>
   & <工具目录的uv.exe> venv --python <工具Python的绝对路径> <工具目录的venv>
   & <工具目录的uv.exe> pip install --python <工具venv的python.exe> 'windows-mcp==0.8.8'
   & <工具venv的windows-mcp.exe> serve --help
   ```

4. 将启动脚本放到工具目录，以活动桌面用户的交互令牌启动；可用唯一命名的按需计划任务，保存任务定义。优先使用该用户正常权限，仅安装或受限操作确有需要时提升。SSH 中只启动同名命令、`SYSTEM`／非交互任务或 `Start-Process` 返回 PID，都不能证明桌面 MCP 可用。经 SSH 调度的非交互辅助进程使用隐藏窗口；取材需要的可见终端则明确在交互桌面最大化打开。
5. MCP 服务仅绑定远端 `127.0.0.1`，例如经端口检查后选用 `8765`。启动轮廓为 `windows-mcp.exe serve --transport streamable-http --host 127.0.0.1 --port 8765`。本机通过 SSH 本地转发连接：`ssh -N -L <本机空闲端口>:127.0.0.1:8765 <沿用已授权SSH连接参数>`。本机 Cursor 项目级 MCP 配置指向转发端口，具体 `/mcp` 路径以已安装版本实际握手为准；不开放新的公网监听或防火墙入站端口。
6. 对该服务设置 `WINDOWS_MCP_SCREENSHOT_SCALE=1.0`、`WINDOWS_MCP_DISABLE_FLASH=1`，尽量保留原尺寸并减少桌面闪光干扰。若后端黑屏或错位，记录后切换上游支持的截图后端再验收。
7. 验收必须包括 MCP 握手、工具列表、显示器清单、远端桌面截图，以及实际最大化一个可见窗口并再次截图。检查窗口标题／会话、截图像素尺寸和实际显示内容相符；仅 HTTP 可连或日志显示 running 不算成功。任务 PID、会话 ID、监听地址和客户端连接信息写入报告。
8. MCP 安装自身也要留过程全屏截图。MCP 尚未就绪时，使用同一远端交互桌面的系统截图能力取得 bootstrap 原图；不能把 MCP 安装前步骤伪装为由尚未可用的 MCP 拍摄。

## 全屏原图要求

用户已确认远端没有敏感数据，本轮截图直接保留原样，不作隐私遮挡。相关浏览器、资源管理器、PowerShell、安装终端、EVS 和教师窗口能最大化的都先最大化；不可最大化的对话框、输出窗按真实能力摆放，记录原因，不拉伸 UI、不改程序来摆拍。配合窗口保持不遮住当前主步骤的关键内容。

截取远端完整显示器画面，保留桌面／任务栏与真实窗口边界，不只截应用控件。多显示器时明确主屏，并保留完整虚拟桌面原图及对应主屏原图，索引写明各图覆盖的显示器。优先使用稳定的 1920×1080 或更高实际分辨率；不足时保留原尺寸并记录，不放大伪造清晰度。缩放固定且文字清楚，不能为了取材频繁更改显示设置。

教程母版使用原始分辨率的无损 PNG，保留原文件，不裁剪、不涂改、不加标注。若 MCP 只返回压缩预览，则预览只用于操作判断，另在相同交互会话通过 Windows 截屏／原尺寸 PNG 能力落盘，并核对尺寸；把 JPEG 改后缀不能算 PNG 母版。以后需要箭头、圈注或裁切，复制到单独的 `tutorial-edits/`，与原图建立对应关系。

按真实关键步骤取图：动作前、动作执行／进度中、结果稳定后。下载安装、解压、校验、选择档位、完成提示、首次启动、切换模型、退出和复装均覆盖；进度阶段约每 15–30 秒取一张有信息变化的画面，避免重复空帧。弹出框、错误和回退触发时另拍；读者需要看到的提示不能一闪而过。失败图保留，重试成功后另存，不能用成功图替换失败记录。

不要静默完成一切后重新打印命令或结果来冒充安装过程。需要教程取材的命令在远端可见且最大化的终端真实执行；SSH 用于调度和辅助读数。对首次操作漏拍，索引标为缺图；允许在新的测试副本重做真实步骤，明确标注补拍轮次与首次／重复安装性质。

## 目录与图片索引

统一存到本轮安装根 `_test_report/tutorial-capture/`：

```text
tutorial-capture/
├─ environment.json            # 系统、版本、会话、屏幕、缩放、工具版本
├─ screenshots-index.csv       # 每张图片的阶段、动作、状态与说明
├─ screenshots-index.json      # 相同索引的结构化版本
├─ raw-fullscreen/              # 原始全屏 PNG，保留所有有效轮次
├─ tutorial-edits/              # 未来制作的派生图；本轮可为空
├─ bootstrap/                   # MCP 就绪之前的远端全屏原图
└─ logs/                        # 对应安装／测试／MCP 日志
```

文件名使用 `0001_<阶段>_<档位>_<before|progress|after|error>_<时间戳>.png`。每图记录文件相对路径、PNG 哈希、像素尺寸、拍摄时间与时区、序号、轮次、会话 ID、屏幕范围、窗口标题／是否最大化、实际动作、命令或日志位置、退出码／测试状态、教程建议图注、是否建议发布以及不适用／缺图原因。使用索引定位日志，不能把只有截屏的片段当成安装成功证据。

具体镜头表见 [安装与首次启动取材表](../beginner/00-SSH安装与首次启动取材表.md)。Windows MCP 是 agent 取材辅助，不能写成普通 EVS 用户必须安装的依赖；初心者主教程仍以安装完成后的 THA3 基础窗口、参数、图层和简易区域晃动为主。
